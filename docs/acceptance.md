# Приёмка единого аудита

Эти 15 контрольных тем размечены командой по конкретной версии ТЗ. Проверяющий скрипт сверяет SHA-256, каждую дословную цитату с указанными строками и наличие вопросов для отдельных решений. Баллы участнику выставляет жюри по четырём критериям. [Исходный документ](https://github.com/BCC-HUB/ai-requirements-validator-task/blob/928c1aa364265426105b69ba7a3444eac11b22db/docs/requirements.md) · [Критерии жюри](https://bcchubagents.mnu.kz/#judging)

Скачайте исходный файл и настройте ключ по [инструкции запуска](../README.md#как-воспроизвести-отчёт). Чтобы проверить именно сдаваемый результат, сформируйте Markdown и JSON одной командой аудита, затем передайте скрипту JSON этого прогона.

```sh
python run.py ../sana1-run/requirements.md ../sana1-run/review.md --language ru --answers --json
python -m tools.check_official_case ../sana1-run/requirements.md --report ../sana1-run/review.json
python -m tools.check_expanded_acceptance ../sana1-run/requirements.md --report ../sana1-run/review.json
```

Для конкурсной приёмки используется русский отчёт, как предписывает § 6 задания. Для проверки автоматического выбора запустите аудит трёх коротких ТЗ на казахском, русском и английском при одном языке интерфейса. Сверьте язык пояснений в результате и скачанном Markdown с языком соответствующего входа. При выборе другого целевого языка сверьте дословные цитаты, ссылки на строки, ID и SHA-256 с исходным аудитом. Содержательную точность перевода оценивает читатель, владеющий целевым языком. [Требования организаторов](https://github.com/BCC-HUB/ai-requirements-validator-task/blob/928c1aa364265426105b69ba7a3444eac11b22db/README.md#6-состав-отчёта)

Для опубликованного `report.json` те же проверки подтвердили шесть отдельных дефектов без повторов, 15 из 15 тем и 111 точных цитат. Ещё 19 замечаний находятся за пределами шестипунктовой разметки. Для прогона правил без ключа используйте отдельные команды. Первая сравнивает исходник с вариантами, где устранены отдельные дефекты. Вторая проверяет все 15 тем. [Файлы проверенного прогона](https://github.com/mansurkenma54/SanA1-Hackathon/releases/tag/jury-2026-11-27)

```sh
python -m tools.check_official_case ../sana1-run/requirements.md
python -m tools.check_expanded_acceptance ../sana1-run/requirements.md
```

В браузере на 390 и 1440 px проверены загрузка примера, переключение темы и языка, уточнение GET → POST, сравнение и скачивание Word. При отключённом провайдере результат явно помечен как выполненный правилами. В тесте подписанного повторного прогона три соседних с правкой блока были перепроверены индивидуально, три неизменённых использованы повторно, все шесть были проверены в составе набора.

Проверка схем сравнивает читаемые подписи. Возможное визуальное расхождение остаётся с низкой уверенностью до сверки. Сканированным PDF нужен текстовый слой. Проверка общедоступных ссылок ограничена восемью адресами за один прогон, HTTP HEAD и пятью секундами. Редирект и ответ 405 требуют ручной проверки.

История прогонов содержит длительность модельных проверок, повторно найденные замечания и изменения в контрольных примерах по версиям. [Архив протокола приёмки](https://github.com/mansurkenma54/SanA1-Hackathon/blob/3110bdd400ed0329c650ffe0a4767c9d83a29c4d/docs/acceptance.md)
